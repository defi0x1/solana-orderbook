# clob

A fast, compute-efficient central limit order book implementation for Solana.

The book is a dense 8,192-tick ring window with two-level occupancy bitmaps.
Makers own their quote set and can replace it atomically with one `MassQuote`
instruction, quotes self-expire by slot TTL, and fills use internal seat
balances without CPI, PDA derivation, or logs on the hot path. It is written in
[Pinocchio](https://github.com/anza-xyz/pinocchio), zero-copy byte-array state
and follows the p-token account-access pattern.

## Compute-unit measurements

These local Mollusk measurements are regenerated by `cargo bench`. The bench
fails when a workload exceeds its checked-in CU ceiling. They measure this
implementation only and are not a cross-project performance comparison.

| Op | CUs | Note |
|---|---|---|
| `cancel` | 249 | O(1) by node back-links — no hint, no walk |
| `place_limit` (add or amend one quote) | 601 | |
| `place_take`, 1 level | 769 | includes taker settlement |
| `place_take`, 5 levels swept | 1,873 | |
| `mass_quote`, 40 levels refreshed in place | 4,409 | ~110 CU per quote update |
| `mass_quote`, 40 levels posted fresh | 13,954 | |
| `reanchor`, 2,048-tick move | 12,357 | authority-gated |
| `reap_expired`, full-window scan | 1,901 | permissionless crank |
| `swap` (2 CPIs) | 13,133 | legacy SPL Token in the benchmark environment |

These are program-execution CUs, not validator scheduler cost. They are useful
for comparing implementations of the same workload, but are not enough to
derive transactions per block: signatures, write locks, requested CU limits,
instruction bytes and loaded account data also affect scheduling. Any
throughput claim must measure those full-transaction inputs separately.

To reduce compute on the common maker path, `MassQuote`, `PlaceLimit`, and
`Cancel` use a custom entrypoint that recognizes their two-account shape and
dispatches directly to the handler. Taker, crank, admin, seat, and error paths
use the standard Pinocchio entrypoint through a `#[cold]` fallback.

## Architecture

One account per market:

| Region | Size | |
|---|---|---|
| Header | 320 B | params, vaults, anchor, seq, free list |
| Bid/ask bitmaps | 2 × 1,040 B | summary + 128 leaf words each |
| Levels | 128 KB | 8,192 × 16 B, ring-indexed (`tick & 8191`) |
| Seats | 10 KB | 128 × 80 B, internal balances |
| Order pool | 30 B × cap | fixed at creation, u16 indices, node 0 reserved |

`NIL = 0` and node 0 is never allocated, so an all-zero region *is* the empty
state — no sentinel rules to remember. Each node stores its side in the spare
high bit of its maker field and carries a 64-bit ABA-resistant order id. Orders
sit on two doubly-linked lists
(level FIFO + per-seat chain), so ending an order is O(1) from any context:
filled, cancelled, expired and evicted nodes are freed on the spot, and there
is no deferred-cleanup state anywhere. Recentering the window moves no
memory — the ring re-labels slots and evicts the vacated edge through seat
refunds. Matching, quoting and cancelling live in pure byte-level Execution
Helpers (`state.rs::BookRefMut`) that never touch `AccountInfo` or CPI.

**Indexing by account update.** The hot path emits nothing, because it does not
need to: the market account is fully self-describing, so an indexer subscribes
to account updates and diffs snapshots. A `u128 seq` in the header, incremented
once per mutating instruction, orders those snapshots and makes a missed one
detectable. Only the rare instructions that create or reconfigure a market log
via `sol_log_data`, since a market coming into existence is the one thing
account updates cannot announce. The Rust client exposes
`snapshot::MarketSnapshot::decode` for the complete bitmap, level, seat and
variable-pool account rather than making indexers reproduce private offsets.

## Workspace

- `program/` — the Pinocchio program (16 instructions, single-byte dispatch)
- `sdk/codama/` — the Codama IDL tree; `npm run generate` renders both clients
- `sdk/rust/`, `sdk/js/` — generated clients (never edit `generated/`)
- `tests/` — Mollusk integration tests + invariant checker + CU bencher
  (`cargo bench`, report in `tests/benches/compute_units.md`)

## Build & test

```sh
cargo build-sbf --manifest-path program/Cargo.toml
cargo test -p clob-tests
cargo bench -p clob-tests --bench compute_units
```

Building the program requires the Solana platform tools.
